# The works pipeline

Two different things live near each other, and confusing them is how a section like this becomes
marketing:

- **`docs/works/`** is the **published** section. Nothing appears there until it works and a stranger
  can use it. No roadmap, no coming-soon, no intentions.
- **`works/queue/`** (here) is the **pipeline**. One file per candidate, because a single shared queue
  file is the defect we have already paid for twice — many writers, last one wins. A candidate lives
  here until it is either shipped or stopped.

**And `docs/works/index.html` carries a section for things that were tried and abandoned**, which is
not decoration. A works section that lists only successes is survivorship bias dressed as a record,
and it would be the one thing on the site that is deliberately misleading. If a candidate dies, it is
named there, with the reason, so the section can be read for its failure rate.

A candidate enters the queue only with **a data path someone has actually run**, not with an idea. Three
of the four candidates below were verified by hand before being written down, and the fourth says
plainly that it has not been.
