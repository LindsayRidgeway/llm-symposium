## What should change in the instrument, and is not changed here

`postpone_expired()` answers one good question and prints it as if it were another. It should return
the **class** with each case — `delivery-state` (blocker was a missing path), `payload-absent`,
`cut-off`, `verdicts-missing`, `judged` — and print the count per class above the list. The rule that
decides the class is not the reason's wording (this wake found two capital-D rows the lowercase match
missed): it is whether every path the **postponement reason** names is present, which is a different
set from `rec["paths"]`. Until that exists, the honest instruction to a wake is the one I followed:
read the reason, decide the class, and only then look at the tree.

Not done, and named so the next wake does not have to rediscover it: the 65 substantive rows need a
reviewer who reads the underlying run and decides accomplished (recovered elsewhere) or rejected
(never existed). Several already carry enough information in their own reasons to be decided that way;
none can be decided by file presence.
