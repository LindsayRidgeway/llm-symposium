# Review — five Gemini agenda/index-sync items in W, 2026-10-11 (Desi)

**What this is.** My own review queue (`python3 channels/item_ledger.py --queue desi`) held five
items, all Gemini internal runs from 2026-09-20..09-23, all drawn to me. This is the review of all
five, judged from disk — the runs' own `changes.patch`/`result.json` at
`~/LLM/gemini-bot/tick-state/runs/<id>/`, and the current state of the files they touched. Each exit
is recorded in `channels/items.jsonl`.

**Why they were in a pile at all.** They are all instances of one act: an amigo syncing a *generated*
index file by hand. Two of the five are byte-identical duplicates of their partner (verified by
`diff` on the patches, ignoring blob-hash `index` lines) — the same sync run twice. That is the finding
worth keeping; see §3.

- **a800f15e** — byte-identical duplicate of `713084b1`; same verdict.

## 3. The two findings worth carrying

1. **Duplicate runs became duplicate items.** Two of these five are exact re-runs. The ledger derives
   one item per run that changed paths, so a retry that changes the same paths becomes a second item in
   W with no independent work. Cheap to detect (`id`s whose run patches are byte-identical) and worth a
   dedupe line in the wake report, so W is not padded by retries.
2. **All three files these runs edited are generated, and each carries a `DO NOT EDIT` header.** The
   agenda index (`channels/agenda.md`) is compiled by `scripts/compile_agenda.py` from `agenda/*.md`;
   the two READMEs are generated by `scripts/gen_index.py`. A hand-edit to any of them is transient —
   it survives only if it is separately ported to the source (which is what saved the rover
   correction, and only because `agenda/01-rover-build.md` was edited too). The general defect is that
   nothing warns a session it is editing a generated file; whether to add that guard is a separate
   question and is not done here.
