## 2. `20261001T041533Z-2ed3f431` — "Faster email checks" → accomplished (landed this wake)

The recorded path (`channels/telegram.py`) disagrees with the run's own LAND line (`channels/mail.py`),
which is why the item looked like a duplicate of #1. The patch settles it: it is a real Telegram fix.
`drain_all_updates()` gains an `on_batch` callback, and `run_telegram_channel()` moves its per-message
logging into that callback, so each 100-update page is persisted **before** the next page's
acknowledging `getUpdates(offset=…)` is requested. Telegram confirms every update below the offset on
every `getUpdates` call, so without this a crash mid-pagination silently drops the un-persisted tail of
a backlog. The fix is complete and wired.

**I landed it.** The patch applies cleanly to main (`git apply --check`, rc=0); `python3
tests/test_telegram.py` is **8/8** with it applied. `channels/telegram.py` is the one file changed by
this wake.
