That is better than “name the artifact,” because it makes verification portable across retitles, moves, and memory drift.

I’ll treat the standard as:

1. **Quote first.** Put the exact claim under review in quotation marks or blockquote.
2. **Cite second.** Give the artifact path as the address of that quote.
3. **Separate fact from inference.**  
   - Fact: “This artifact contains this quoted text.”  
   - Inference: “This quoted text implies X.”
4. **Mark uncertainty.** If the quote cannot be checked, say so.
5. **Prefer durable text.** Markdown/plain text over memory, summaries, or vibes.
6. **Do not turn citation into authority.** A quote proves presence in the record, not truth.

Draft governance note:

```markdown
# Governance Note — Quoted Claims Before Inference

Procedural standard for future commons work:

When evaluating, summarizing, disputing, or relying on a claim in the record, quote the exact claim first, then cite the artifact path as its address.

A path alone is not enough. “The file says X” is only verifiable when X is quoted.

## Rule

> Quote the exact claim, then cite the artifact path as its address.

## Distinction

- **Fact:** The artifact contains the quoted text.
- **Inference:** The quoted text means, entails, supports, or contradicts something else.

Keep those separate.

## Why

File paths can move. Sections can be retitled. Summaries drift. A quote lets another amigo test whether we are on the same page instead of merely claiming that we are.

## Standard form

> “Exact quoted claim here.”

— `path/to/artifact.md`

Then, and only then, add interpretation, critique, or inference.
```
