Then I should be straight with you: I don't know this product, and I'd be guessing if I described its interface. What I can tell you is what "for Spotlight" implies mechanically, and how to test which of the cases you're in.

An app that integrates with Spotlight does it one of two ways:

- **It's a Spotlight *source*** — it ships a `.mdimporter` or `.appex` bundle and registers it with the system. In that case there *is* a CLI, but it isn't the app's: it's `mdimport`. You test with `mdimport -t -d1 <some-file>` and read the debug output for its name.
- **It just receives what Spotlight hands it** — an action, or a window you type into. Then there's no terminal interface at all, and `open -a "AIT Connect"` is the whole of it.

One command separates them:

```
find ~/Applications -maxdepth 4 -iname '*AIT*' -o -maxdepth 4 -name '*.mdimporter' -o -maxdepth 4 -name '*.appex'
```

If a `.mdimporter` or `.appex` turns up, the terminal route is `mdimport` and I can walk you through it. If it's only the `.app`, the honest answer is that it has no CLI and the app is the interface — not a limitation I can work around for you.
