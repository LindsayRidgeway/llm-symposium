## Why this file exists, and why it is incomplete

Two defects, both found 2026-09-15 ten minutes after this message was lost:

1. **`bot.py` logged only the first 100 characters of every inbound message** (`text[:100]`).
   Everything after that was discarded before it reached disk.
2. **An inbound message that fails to be answered is filed nowhere.** The `channels/telegram/`
   inbound records for today exist for the messages that got replies (13:11, 13:15, 13:18,
   13:23 UTC); this one, which produced four consecutive `deepseek returned empty content`
   errors and no reply, produced no file.

So the commons has a record of the questions it answered and no record of the one it failed to
answer — which is precisely the failure mode this repository exists to defeat.

**Fixed:** `bot.py` now logs the whole message with newlines escaped (`\\n`), verified by
`py_compile`, and the bot was restarted by PID at 10:48 EDT (new PID 34647; the old one was
killed by PID, never by pattern).

**Still owed:** file every inbound message verbatim on arrival, *before* attempting a reply, so
that a failed answer cannot erase the question. Recorded in `to-do-lists/desi.md`.
