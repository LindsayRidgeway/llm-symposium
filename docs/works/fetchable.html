Which public data you can actually get

Thirty-five public sources — trials, papers, genomes, weather, quakes, statistics, books. Each was asked three separate questions, because the answers do not agree: does it answer with no account, can a web page read it, and did data actually come back. Your browser re-checks the middle one itself, because that is the only place it can be settled.

The useful finding is not how many sources are open. It is that six of them answer a server happily and are invisible to a browser — so "you can just fetch it" is true or false depending on which one you are, and a page that assumes the server's answer will fail in front of a reader.

What this is, and what it is not

  • It is a measurement taken on one day, from one machine, with one polite request per source. It is dated above and the exact request for every row is printed under it. APIs change, block, and add paywalls without telling anyone; re-run a row and you may get a different answer. This is a snapshot, not a guarantee.
  • "Readable from a web page" is not the same as "open". That column is CORS — the rule a browser enforces and a server-side script never sees. Europe PMC, arXiv, Wikidata, the WHO, JPL and the CDC all answered us fine and send no CORS header, so a page like this one cannot read them at all. It says nothing about their terms: a source can be closed and readable, or open and unreadable.
  • A key is not the same as a wall. Four sources advertise one. Some are free and instant (NASA's shared DEMO_KEY answered this page), some are throttled, and one wants an account. The column says "the documentation asks for a key", not "you cannot have it".
  • Rate limits were not measured systematically and are the likeliest reason a row still works for you at a different speed. Two sources throttled the measurement itself — GDELT asked us to slow to one request per five seconds, Semantic Scholar refused outright — and both are recorded as they answered, not as they are advertised.
  • "Answered" does not mean "good". One sample request came back, not a corpus. Nobody here judged accuracy, completeness, licensing or terms of use, and none of these sources is ours. If you build on one, read its terms and its own documentation — we are not affiliated with any of them and cannot speak for them.
  • It does not tell you what is true. It tells you what is reachable. Those are different questions, and confusing them is how a tool like this misleads someone.

How it was measured

One script, scripts/measure_sources.py, requests each sample URL once with no credentials, sending Origin: https://lindsayridgeway.github.io so the CORS answer is visible in the response headers. It records the status code, the CORS header, the content type, the byte count and the first characters of the body. A 200 with an empty body is not a pass. The results are in docs/works/fetchable-sources.json and this page renders exactly that file — it does not retype the numbers. The browser test below is the part a script cannot do.
